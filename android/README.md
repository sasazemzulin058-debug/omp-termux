# oh-my-pi on Termux (Android, aarch64)

This directory is the entire Android/Termux overlay for
[oh-my-pi](https://github.com/can1357/oh-my-pi). It is a thin,
patch-based fork: the upstream source is left untouched on disk, and a
deterministic overlay (plus a set of legacy patches) adapts the native Rust
addon to Android's bionic libc. Everything Android-specific lives here.

## Layout

```
android/
├── patches/        # legacy source patches applied onto upstream (git apply)
├── scripts/        # apply/verify overlay, build, install, regen, CI helpers
└── docs/           # architecture, CI/CD, verification, setup, port-changes
```

## Quick start (end user)

On any aarch64 Termux session (Android 14+ / API 34+):

```sh
curl -fsSL https://raw.githubusercontent.com/sasazemzulin058-debug/omp-termux/main/quickstart.sh | sh
omp --version
```

GitHub Actions builds and publishes one `omp-termux.tar.gz` app archive
plus checksum. The device only installs Termux's packaged `bun`; no `npm`,
`bun install`, Rust, clang, source clone, proot, or `glibc-runner`.

## How the port is delivered

Two mechanisms, both living in `android/`:

1. **Deterministic overlay (current)** — `scripts/apply-overlay.py` applies
   8 checked transformations to a fresh upstream tree
   (Cargo.toml arboard+pi-voice gating, lib.rs, crash_handler.rs,
   clipboard.rs, pi-shell process.rs, pi-builtins proc_snapshot.rs + ps.rs,
   loader-state.js). `scripts/verify-overlay.py` proves the result (10
   gates). The sync bot and the on-device build both use it.
2. **Legacy patches (maintenance/old checkouts)** — `patches/01-06-*.patch`
   applied by `scripts/apply-patches.sh`, regenerated by
   `scripts/regen-patches.sh`.

In-tree stubs (not patches): `crates/pi-natives/src/audio.rs` and
`src/live.rs` replace the pi-voice audio/WebRTC surfaces with error-returning
stubs on Android, because the pi-voice + webrtc/opus graph OOM-kills free
GitHub runners.

### The patches (legacy set, one concern each, applied in numeric order)

| Patch | File | Why |
| ------- | ------ | ----- |
| 01 | `crates/pi-natives/Cargo.toml` | Gate `arboard` to non-Android (no bionic clipboard backend) |
| 02 | `crates/pi-natives/src/lib.rs` | Drop nightly-only `feature(alloc_error_hook)` |
| 03 | `crates/pi-natives/src/crash_handler.rs` | Disable the alloc-error hook; keep tests via `#[allow(dead_code)]` |
| 04 | `crates/pi-natives/src/clipboard.rs` | Android cfg gates + stubs for clipboard fns |
| 05 | `crates/pi-shell/src/process.rs` | Enable the Linux `platform` module on `target_os = "android"` |
| 06 | `packages/natives/native/loader-state.js` | Add `android-arm64` to `SUPPORTED_PLATFORMS` |

A critical detail: for the `aarch64-linux-android` target, `rustc` sets
`target_os = "android"` and **`target_os = "linux"` is false**. Patch 04
keeps the Linux clipboard path gated on
`all(target_os = "linux", not(target_os = "android"))` so the arboard-backed
code is never selected on Android, and patch 05 uses
`any(target_os = "linux", target_os = "android")` for the shared process
module.

## Maintenance

### Overlay (sync bot path)

`.github/workflows/sync-upstream.yml` imports upstream main, runs
`apply-overlay.py`, verifies, commits `chore: sync upstream OMP <version>`,
tags `v<version>-termux`, and pushes. Manual equivalent:

```sh
python3 android/scripts/apply-overlay.py   # fails loudly on drift
python3 android/scripts/verify-overlay.py  # 10 gates + version/tag check
# re-stub crates/pi-natives/src/{audio,live}.rs by hand after a sync
```

### Legacy patches

Patches are stored as `git diff` output and validated with
`git apply --check`. To rebase onto a newer upstream:

```sh
git fetch upstream && git merge upstream/main   # or rebase
android/scripts/apply-patches.sh                 # apply; fails loudly on drift
# ... fix conflicts in the 6 target files by hand ...
android/scripts/regen-patches.sh                 # rewrite patches from the tree
git checkout -- crates/ packages/                # reset tree to clean upstream
```
